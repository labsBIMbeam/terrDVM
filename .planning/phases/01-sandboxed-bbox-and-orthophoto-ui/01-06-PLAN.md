<objective>
Deliver the live orthophoto preview on top of the approved two-role source policy: a TDD correlated preview state machine (stale suppression, abort-on-clear, exact denied/timeout/failed states), the bounded imagery request path through the sole adapter, the full UI-SPEC preview-state UI with honest fixture labeling and correct two-variant attribution, and a built-artifact Paja `preview-ready-live` case whose verdict is derived from the rendered DOM, the live policy status, and request/bbox correlation — never from a harness flag. If live preview cannot pass, the phase stays blocked; the fixture is never substituted.

Purpose: MAP-05 is the phase's headline promise — the preview must correspond to the active bbox and be provably live. Correlation bugs (A1) and honesty bugs (fixture dressed as live) are the two ways to fake it; this plan tests both away and hardens the runner so the live gate can never silently degrade.
Output: preview-machine + preview-request + preview-pane wired into the app, two unit test files, the preview-ready-live manifest case with redacted evidence, and the runner upgraded to a hard --require-live step. Zero installs; no local fallback surface.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Selected bbox → imagery request | User-controlled coordinates parameterize an outbound bounded request |
| Adapter responses → preview pane | Response bytes and timing decide user-visible truth claims (live vs not) |
| Test fixture → acceptance surface | The fixture must never cross from test feed into live evidence |
| Built artifact → network | Imagery path must not open any egress beside the sole adapter |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-01-31 | Tampering | Stale response replacing newer selection's preview | high | mitigate | Revision-correlated machine, abort-on-clear, named cases 17-18, built-browser second-draw assertion in preview-ready-live |
